# YouTube watch-page recovery — QA 2026-09-22

## Исправляемая регрессия

Пользовательская ссылка: https://www.youtube.com/watch?v=XFl4q2FfkVg

Прежний fallback из QA 2026-09-15 заменял весь body карточкой thumbnail + title,
если текста было меньше 500 символов. Это скрывало отсутствие клиентского интерфейса
и не давало пользователю ни рекомендаций, ни комментариев. Причина воспроизведена:
YouTube присылает `ytInitialData` с 20 рекомендациями и continuation комментариев,
но большой клиентский JS по-прежнему превышает допустимые 6 МБ. Нативный DOM содержит
только время плеера, skeleton и оболочку приложения.

## Что изменилось

- `server/youtube.ts` читает фактически полученные данные ролика/канала/описания,
  рекомендации (старый compactVideoRenderer и новый lockupViewModel) и первую
  страницу комментариев. Порядок рекомендаций и comment threads сохраняется,
  дубликаты и непоказанные reply entities исключаются.
- Если native UI не появился, создаётся читаемый snapshot с двумя колонками,
  крупным качественным thumbnail, каналом/описанием, рекомендациями справа и
  комментариями снизу. Это облегчённая верстка из реальных данных YouTube,
  не полная работа родного JS-приложения. На странице есть подпись snapshot.
- Максимум 20 рекомендаций и 20 комментариев. Единственный дополнительный API endpoint
  фиксирован: POST `/youtubei/v1/next?prettyPrint=false` для чтения комментариев.
  Вызов использует исходный публичный context/token той же страницы и общий guardContext.
  Команды/действия/URL из renderer payload не исполняются; аккаунт не используется.
- На уже отрисованной native странице добавляются только отсутствующие разделы.
  Thumbnail заменяет только плеер. Удаление body по длине текста убрано.
- У YouTube начальный `#player.skeleton` и `#watch-page-skeleton` находятся рядом
  с ytd-app. Эти две подтверждённые загрузочные заглушки удаляются после восстановления,
  иначе старый чёрный плеер дублировал/перекрывал новый снимок.
- Картинки не запрашиваются для созданных, но не вставленных DOM-веток.
  Превью основного ролика выбирается из предоставленных больших источников.
- Описание сокращается в самом DOM до первых четырёх строк. CSS overflow не используется:
  скрытые строки не должны порождать невидимые игровые фрагменты.
- Ошибка comments API сохраняет остальную страницу и выводит явное сообщение.
  Данные выводятся через textContent, не через innerHTML.
- Исправлен поздний recovery: прежний резерв 20–23 секунды мог запрещать догрузку
  комментариев/картинок даже при достаточном остатке общего deadline. Для ограниченной
  восстановленной страницы резерв capture составляет 8 секунд; API comments до 4,5 с,
  assets до 3,5 с. Общий deadline 55 секунд не увеличен.

## Ограничения безопасности и формата

Транспорт `server/security.ts`, `server/network.ts` в этой итерации не менялся.
Сохранены 180 попыток, 6 МБ на ресурс, 24 МБ суммарно, SSRF/IP/DNS/redirect/port
проверки и pinning, запрет media/WebSocket/Service Worker/downloads. Все новые
картинки и comments API проходят тот же транспорт и общий бюджет.
Level, partition/exclusive coverage и игровая механика не менялись.

## Оставшиеся ограничения

- Только первая порция комментариев; ответы и бесконечная подгрузка не раскрываются.
- Рекомендации — публичные результаты анонимного запроса, могут отличаться от персональных.
- Формат внутренних данных YouTube может меняться; неизвестная схема диагностируется,
  отсутствующий текст не выдумывается. Авторизация, consent/age/region walls не обходятся.
- Видео остаётся thumbnail; большой JS и видеопотоки не разрешены. Полное воспроизведение
  native YouTube UI не заявляется.
- Это исправление snapshot, а не завершение fidelity-редизайна WEBIVORE или модели шара/кролика.
