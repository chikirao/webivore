## Реализация

- `server/snapshot.ts`: отдельный browser/context/job, монотонный deadline 55 секунд,
  отмена и закрытие browser в finally. Глобальный busy остался только admission control.
- `server/readiness.ts`: содержательный видимый текст/изображения, стабильность текста,
  высоты документа и изображений, состояние шрифтов. Network quiet — дополнительный
  сигнал; стабильное содержимое проходит даже при активной аналитике.
- Первая стадия ограничена 6,5 с. Затем прокрутка шагом 700 px, повторное чтение высоты,
  активация lazy images, decode видимых img/background-image, ожидание fonts.ready,
  заключительная стабилизация до 2,5 с. Подготовка уступает оставшееся время захвату
  (около 20 секунд), а не расходует весь общий deadline.
- Незавершённые необязательные запросы отменяются при переходе к capture.
  JavaScript страницы замораживается через CDP до extract и tiled screenshot.
  Sticky/fixed переводятся в обычный поток до извлечения, а не повторяются на каждом tile.
- Для YouTube watch/shorts/embed с валидным video ID используется guarded
  `https://i.ytimg.com/vi/{id}/hqdefault.jpg`, если настоящего доступного кадра нет.
  При skeleton-only странице получается явно подписанная карточка thumbnail + название;
  при содержательном интерфейсе заменяется область плеера. Это документированный fallback,
  а не заявление о полностью загруженном интерфейсе YouTube.
- Обычное video: сохранение уже доступного кадра либо poster, иначе подписанная область
  «Video preview unavailable». Видеопоток не разрешается.
- GET повторяется не более одного раза при временной сетевой ошибке или
  408/429/502/503/504, backoff 180 мс. POST не повторяется; метод и небольшое тело сохраняются.
- `diagnostics` в ответе содержит причины отказов, использованные запросы/байты,
  число незавершённых запросов перед capture, missing images/backgrounds, fonts,
  media fallback, partial readiness/navigation и время. Игровые поля Level сохранены.
- Vite исключает `artifacts/**` из watcher: запись GIF под Windows иначе вызвала
  EBUSY и остановила dev-сервер. Два промежуточных игровых прогона прервались из-за
  watcher/перезапуска API во время разработки; итоговый прогон выполнен целиком.

## Безопасность

Остались 180 сетевых попыток, 6 000 000 байт на ресурс, 24 000 000 байт суммарно,
55 секунд на snapshot. Retry входит в общий счётчик. Script/xhr/fetch допускаются
только до 160 попыток / 20 МБ; остаток доступен изображениям, CSS, шрифтам и документу.
Ограничение применяется также к уже текущему чтению потока. Content-Length позволяет
отклонить заведомо слишком большой ответ до накопления body; chunked поток проверяется
по фактически пришедшим байтам. Как и раньше, сетевой chunk, пересекающий границу,
может уже быть получен, но не включается в возвращаемый ресурс.

Сохранены проверка URL/портов, запрет private/local/metadata/IPv6, проверка всех DNS A
ответов и pinning публичного IP. Redirect Location дополнительно проверяется перед
fulfill; следующая загрузка снова проходит DNS/IP validation. Существующая обработка
VPN fake-IP через проверяемый публичный DNS сохранена без изменений. WebSocket,
Service Worker, media и downloads не разрешались. Нет route.continue и нет production
исключения для localhost fixtures. Fixture-транспорт инъецируется только тестами.

## Ограничения

- Pexels после первоначального успешного захвата блокирует автоматизированные обращения
  HTTP 403; финальный live atlas для него получить не удалось. Lazy behavior проверен
  воспроизводимым fixture и полнотой изображений захватываемой области Wikipedia.
- YouTube проверен на указанном публичном watch URL. DRM, авторизация, age gates,
  региональная недоступность и consent redirects могут потребовать другого публичного URL.
  Thumbnail требует доступности CDN и оставшегося бюджета; недоступный poster не выдумывается.
- Consent/dialog наличие диагностируется эвристически. Кнопки принятия cookies не нажимаются;
  сторонний overlay может остаться частью документа. На итоговых успешных URL такой overlay
  не обнаружен. Нет утверждения, что произвольные consent стены решены.
- Универсальная readiness является ограниченной эвристикой: контент, который появляется
  только по пользовательскому действию или после исчерпания readiness window, не гарантирован.
  Очень маленькая страница без достаточного содержимого может дойти до partial readiness.
- Сохраняются существующие ограничения 1280 px ширины, 9000 px высоты, DOM-бюджет и
  текущая геометрия шара/кролика. Этот QA не объявляет завершённым fidelity redesign.

После завершения итоговых live/browser прогонов выполнена проверка Win32_Process:
оставшихся `chrome-headless-shell.exe` — **0**. Процессы пользователя не завершались.
Локальные API/Vite оставлены запущенными для ручной проверки.
